Output: three entitlement plists, two hook scripts, a PowerShell signer, two assertion scripts, package.json wiring, and unit tests.
</objective>

<interfaces>
electron-builder 26.15.3 (installed, code-verified in RESEARCH):
- `mac.sign: "<path>"` hook is called as `sign(opts, packager)` only when a Developer ID identity was found; `opts.optionsForFile(filePath)` returns `{ entitlements, hardenedRuntime, timestamp, requirements, additionalArguments }`. Default: app bundle -> `entitlements`, everything else -> `entitlementsInherit`. The hook runs before `notarizeIfProvided` (macPackager.js:318-334).
- `@electron/osx-sign` 1.3.3 is bundled with electron-builder; resolve it with `require.resolve('@electron/osx-sign', { paths: [require.resolve('app-builder-lib')] })` and call `signAsync(opts)`.
- `win.signtoolOptions.sign: "<path>"` hook is called once per file per hash with a config object that has `path` (and `hash`). When a custom hook exists, the `cscInfo == null` short-circuit is skipped (windowsSignToolManager.js:132-160). `signIf` swallows per-file failures (winPackager.js:116-120), so the post-build assertion script is required.
- Setting `win.azureSignOptions` switches electron-builder to its Azure manager with an unpinned `Install-Module TrustedSigning -MinimumVersion 0.5.0 -Force`. It must never be set.

ArtifactSigning PowerShell module 0.1.20 (PSGallery, Microsoft): `Invoke-ArtifactSigning -Endpoint <url> -CodeSigningAccountName <name> -CertificateProfileName <name> -Files <path> -FileDigest SHA256 -TimestampRfc3161 http://timestamp.acs.microsoft.com -TimestampDigest SHA256` (parameter names from Azure/artifact-signing-action action.yml).

Env contract (consumed by release.yml in plan 02-11):
- macOS: `CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_API_KEY` (path to .p8), `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`.
- Windows: `AZURE_SIGNING_ENDPOINT`, `AZURE_SIGNING_ACCOUNT`, `AZURE_CERT_PROFILE`, `SPINARR_REQUIRE_SIGNING` ('1' on tag builds with credentials).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner -> signing service | Credentials and file paths cross into codesign/notarytool and the Azure signing endpoint |
| PSGallery -> Windows runner | Signing module code is downloaded and executed with signing credentials in scope |
| electron-builder -> hook | Hook receives file paths chosen by the packager |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | build/entitlements.*.plist | mitigate | disable-library-validation only in entitlements.engine.plist, applied by isEnginePath(); entitlements.test.js and verify-mac.sh assert helpers/app never carry it (SF-6) |
| T-02-02 | Tampering | build/sign-win.ps1 module load | mitigate | Import-Module ArtifactSigning -RequiredVersion 0.1.20 plus loaded-version assertion; azureSignOptions never set, so electron-builder's unpinned Install-Module never runs |
| T-02-03 | Tampering | build/sign-win.js command construction | mitigate | execFileSync with an argv array, no shell; unit test passes a path with ; $( ) and backticks verbatim |
| T-02-04 | Repudiation | unsigned file passing as signed | mitigate | Hook throws under SPINARR_REQUIRE_SIGNING=1; sign-win.ps1 re-checks Authenticode Valid per file; verify-win.ps1/verify-mac.sh assert every binary by glob (Pitfall 5) |
</threat_model>
