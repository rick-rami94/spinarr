<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull_request runs -> signing secrets | Same-repo PR runs of release.yml must never see signing credentials |
| published release -> users | Assets and tag must not change after publication |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Information Disclosure | signing secrets | mitigate | Secrets live only in environment `release`, which only v* tag refs can deploy to; created before any workflow references it so GitHub cannot auto-create it unprotected |
| T-02-09 | Tampering | published release assets | mitigate | Immutable Releases enabled (verified via gh api); docs forbid publishing before verification |
| T-02-10 | Spoofing | users told to bypass OS protections | mitigate | README bypass instructions removed; verification guide uses gh attestation / cosign with the exact workflow identity |
</threat_model>
