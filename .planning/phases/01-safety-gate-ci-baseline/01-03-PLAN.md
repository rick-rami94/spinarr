<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party actions -> runner | Action code runs with the job token and can poison artifacts |
| package registries (npm, PyPI, GitHub releases) -> CI | Downloaded tools execute in CI |
| CI caches -> release artifacts | A poisoned cache could flow into published installers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Tampering | Mutable action tags (tj-actions class) | mitigate | 40-char SHA pins + version comments in both workflows; zizmor `unpinned-uses` gate in `audit`; Dependabot github-actions keeps them fresh |
| T-01-12 | Tampering | release.yml caches | mitigate | Remove `cache: npm` and the `actions/cache` engine-deps step from release.yml |
| T-01-13 | Tampering | meson / zizmor from PyPI | mitigate | Exact versions with `--require-hashes` requirements files |
| T-01-14 | Tampering | Windows oracle zip | mitigate | Pinned URL + SHA-256 recomputed on every run, including cache hits; test-only, never packaged |
| T-01-15 | Elevation of Privilege | Job token scope | mitigate | Top-level `contents: read`; `contents: write` only on the release job; `persist-credentials: false`; zizmor gets the read-only `github.token` |
| T-01-16 | Information Disclosure | Vulnerable Electron shipped unnoticed | mitigate | Electron-targeted audit fails on any advisory; whole-tree audit at high; `npm audit signatures` |
| T-01-SC | Tampering | npm/pip installs in CI | mitigate | Research Package Legitimacy Audit: c8, zizmor [OK], meson approved; no [ASSUMED]/[SUS] packages, so no human legitimacy checkpoint required |
</threat_model>
