<objective>
Close CR-01 and WR-08 in the main process: tie scan consent to the identity of the scanned medium instead of its path, drop consent when the medium changes or disappears, and re-check the gate at every point an engine process can be spawned against a source (probe, enqueue, pump, start).

Purpose: SAFE-01's invariant is "no disc is ever scanned unsandboxed without the user's click". Today `probe`/`enqueue` only check `scans.has(path)`, the Map is never invalidated, and `pump()` never re-checks, so a different disc at `D:\` or an overwritten `.iso` is parsed unsandboxed by ffprobe/ffmpeg with no prompt (01-VERIFICATION.md truth #1, 01-REVIEW.md CR-01, WR-08).

Output: `lib.mediumIdentity` with unit tests, and a main.js where every unsandboxed engine spawn against a source is gated on "scanned with consent AND still the same medium".

Scope note: this is filesystem identity (device / volume serial, file IDs, sizes, timestamps), deliberately NOT the DVDDiscID / Blu-ray disc_id scan catalog, which is Phase 3 (ROADMAP Phase 3 success criterion 1). Do not build a catalog here. Consent stays per-scan and never remembered (D-03): this plan only narrows what an existing consent covers.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| removable media / image file -> main process | Disc and image bytes are untrusted; the medium at a path can change at any time (eject, drive-letter reuse, file overwrite) |
| renderer -> main IPC | `probe` / `rip` arguments come from the renderer and may name any validated path |
| main -> unsandboxed engine | With the sandbox off, ffprobe/ffmpeg/dvdinfo/bdinfo parse the source with the user's privileges |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-31 | Elevation of Privilege | handle('probe'), enqueue() in app/main.js | mitigate | assertScanGate requires a consented scan whose lib.mediumIdentity still matches; mismatch deletes the entry and throws RESCAN_CHANGED (CR-01) |
| T-01-32 | Elevation of Privilege | pump()/prepareBluray()/start() queued jobs | mitigate | assertScanGate re-run at all three spawn-site checks: top of pump(), top of prepareBluray() before its ffprobe, and immediately before the ffmpeg spawn in start(); failure finishes the job as failed (WR-08) |
| T-01-33 | Tampering | scan() mid-scan swap | mitigate | identity captured before and after readInfo; differing identity discards the scan |
| T-01-34 | Spoofing | crafted disc mimicking volume serial, file IDs, sizes and timestamps of a consented disc (Windows) | accept | revalidateScans on every volume change drops entries for vanished media, so an eject clears consent before a re-insert; residual risk documented in SECURITY.md (plan 01-12); Phase 3 disc-ID catalog and Phase 4 Windows sandbox remove it |
| T-01-35 | Tampering | TOCTOU between start()'s check and ffmpeg opening the source | accept | window is milliseconds and requires a local writer racing the spawn; sandboxing (Phase 4) is the real fix |
| T-01-36 | Denial of Service | mediumIdentity stat walk on large Blu-ray trees | mitigate | MAX_IDENTITY_ENTRIES = 5000 cap with a count line; only computed when the sandbox is off or on volume change |
</threat_model>
