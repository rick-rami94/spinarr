## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local repo -> public GitHub | Pushing the branch publishes everything tracked on it |
| maintainer -> repo settings | Admin API calls change how vulnerability reports and dependency alerts reach the maintainer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `git push` of milestone/v1.0 | mitigate | Pre-flight `git ls-files` grep for audit file names (Task 2 step 1); push only after the Task 1 approval |
| T-01-02 | Repudiation | Lost vulnerability reports (SF-3) | mitigate | Private vulnerability reporting enabled and verified via GET (Task 3); fallback email added in plan 01-05 |
| T-01-03 | Tampering | Vulnerable dependencies unnoticed | mitigate | Dependabot alerts + automated security fixes enabled (Task 3) |
| T-01-04 | Elevation of Privilege | Draft PR from a branch in the same repo | accept | Same-repo branch by the sole maintainer; workflows keep `permissions: contents: read` and `persist-credentials: false` |
</threat_model>
