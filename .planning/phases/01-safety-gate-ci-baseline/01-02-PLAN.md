<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> main IPC | Every argument is untrusted; main validates and decides |
| disc data -> engine | Hostile disc structures parsed by dvdinfo/bdinfo/ffprobe/ffmpeg |
| test env -> packaged app | Test hooks must never take effect when packaged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Elevation of Privilege | `handle('scan')` | mitigate | `lib.scanGate` refusal unless `sandboxTrusted()` or `validateScanOptions(opts).userConfirmed === true` |
| T-01-06 | Elevation of Privilege | `handle('probe')`, `enqueue()` | mitigate | Refuse when `!sandboxTrusted() && !scans.has(source)`, so neither parses an unscanned disc unsandboxed |
| T-01-07 | Tampering | `userConfirmed` IPC flag | mitigate | Strict `=== true`; non-object options throw 'Invalid scan options' (unit truth table) |
| T-01-08 | Elevation of Privilege | Compromised renderer sends `userConfirmed: true` itself | accept | Residual: renderer is our own sandboxed, CSP-locked page; gate defends against logic bugs. Documented in SECURITY.md (plan 01-05) |
| T-01-09 | Tampering | `SPINARR_TEST_HOME` / `SPINARR_NO_SANDBOX` in a shipped build | mitigate | Both read only when `!app.isPackaged`; neither skips the consent gate |
| T-01-10 | Tampering | `open-dvdcss-page` -> `shell.openExternal` | mitigate | Handler and bridge entry deleted; `sec_renderer_isolation` asserts the exact bridge key list |
</threat_model>
